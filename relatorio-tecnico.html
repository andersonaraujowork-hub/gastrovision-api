1. Descrição da Arquitetura

A GastroVision API é um sistema backend desenvolvido em Spring Boot 3 com Java 21, seguindo uma arquitetura em camadas bem definida. O objetivo da Fase 1 é fornecer o gerenciamento completo de usuários do sistema de gestão de restaurantes.

Tecnologias Utilizadas

TecnologiaVersãoFinalidade
Java21Linguagem principal
Spring Boot4.0.xFramework base da aplicação
Spring JDBC (JdbcClient)—Acesso ao banco de dados com SQL nativo
Spring Data JPA / Hibernate—Mapeamento ORM e criação automática das tabelas
MySQL8.0Banco de dados relacional
Docker / Docker Compose—Containerização e orquestração

Estrutura de Pacotes

br.com.gastrovision.api
├── controllers        → Camada de entrada HTTP (REST)
├── services           → Regras de negócio
├── repositories       → Interface de contrato do repositório
│   └── UserRespositoryImp → Implementação com JdbcClient (SQL nativo)
├── entity             → Entidades JPA (User, Address, UserType)
└── dtos               → Objetos de transferência de dados
    ├── LoginRequestDto
    ├── PasswordUpdateDto
    ├── UserRequestDto
    └── AddressDto

Fluxo das Requisições

Toda requisição HTTP passa pelas seguintes camadas:

HTTP Request → Controller → Service → Repository (JdbcClient) → MySQL → Response

  • Controller: recebe a requisição, valida o formato e delega ao Service.
  • Service: aplica as regras de negócio e usa Assert.state() para validações críticas.
  • Repository: executa SQL nativo via JdbcClient, sem uso de métodos derivados do Spring Data.

Versionamento de API

Todos os endpoints são prefixados com /api/v1, garantindo versionamento via URL conforme requisito do projeto.

PUT /api/v1/users/{userid} — Atualizar dados (exceto senha)

Request Body: mesmo formato do POST.

Response: 204 No Content

PATCH /api/v1/users/{userid}/password — Trocar senha

Request Body:

{
  "newPassword": "novaSenha456"

7. Execução com Docker Compose

Pré-requisitos

  • Docker Desktop instalado e em execução;
  • Arquivo .env configurado na raiz do projeto.

Configuração do arquivo .env

Crie um arquivo .env na raiz do projeto com as seguintes variáveis:

MYSQL_USER=gastro
MYSQL_PASSWORD=gastro123
MYSQL_DATABASE=db_gastrovision
MYSQL_ROOT_PASSWORD=root123

Subindo a aplicação

Execute o comando abaixo na raiz do projeto:

docker-compose up --build

O Docker Compose irá:

  1. Baixar a imagem do MySQL 8.0;
  2. Fazer o build da aplicação Spring Boot via Dockerfile multi-stage (Maven + JRE Alpine);
  3. Aguardar o MySQL ficar saudável (healthcheck) antes de iniciar a aplicação;
  4. Criar automaticamente o banco db_gastrovision e a tabela tb_users.

Portas expostas

ServiçoPorta
API (Spring Boot)8080
MySQL3306

Verificando o funcionamento

Após subir, acesse:

  • API: http://localhost:8080/api/v1/users?page=1&size=10
  • Swagger: http://localhost:8080/swagger-ui.html

Parando a aplicação

docker-compose down
